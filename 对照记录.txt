**选料**：五花肉，肥瘦三层分明，带皮，切 3 厘米见方。

**步骤**：
1. 冷水下锅焯肉，加姜片、料酒，水开后煮 2 分钟，捞出温水冲净——去腥且不易柴。
2. 锅里少油，放冰糖小火炒糖色，冒小泡转枣红时立刻下肉翻炒上色。
3. 加姜片、葱段、八角、桂皮，烹料酒、生抽、老抽，加热水没过肉。
4. 大火烧开转小火炖 40–60 分钟，肉用筷子能轻松插入即可。
5. 开盖大火收汁，边收边翻，汤汁浓稠挂肉就关火。

**几个关键点**：
- 全程加热水，加冷水肉会发紧变柴；
- 糖色宁浅勿深，炒过头发苦；
- 盐后放，早放盐肉不易烂；
- 想更香可加一勺腐乳汁或几颗山楂，解腻又易软。

按这个做，基本是入口即化、色泽红亮的效果。

----- B 组：删掉那一句 -----
PyTorch 自动微分基于**动态计算图**和**反向模式自动微分**。

前向传播时，每个 `requires_grad=True` 的 Tensor 参与运算，会生成新 Tensor，并记录其 `grad_fn`，指向产生它的 Function，从而动态构建计算图。叶子节点保留 `.grad`。

反向调用 `loss.backward()` 时，autograd 引擎从输出开始，按拓扑逆序遍历图，对每个 Function 调用其 `backward`，用链式法则计算局部梯度并乘以上游梯度，最后累加到输入的 `.grad` 中。

中间结果默认不保留梯度，每次前向重新建图，因此支持动态控制流。也可用 `torch.autograd.Function` 自定义前向和反向。注意梯度默认累积，训练时需 `zero_grad()` 清零。

# Kubernetes Pod 调度算法

kube-scheduler 通过 watch API Server 发现 `spec.nodeName` 为空的 Pod，为其选节点，分三步：

**1. 过滤（Filter）**：遍历所有节点，用谓词逐一排除不满足硬性条件的节点——资源是否够（NodeResourcesFit）、污点容忍（TaintToleration）、节点亲和（NodeAffinity）、Pod 亲和/反亲和、端口冲突、节点状态（Ready、不可调度）等。剩下的是可行节点集合。

**2. 打分（Score）**：对可行节点按多个优先级函数打分（0–100），再加权求和。常见插件有 NodeResourcesBalancedAllocation（资源均衡）、ImageLocality（镜像本地性）、InterPodAffinity 等。得分最高者胜出。

**3. 绑定（Bind）**：把结果写入 Pod 的 `nodeName`，kubelet 随后接管拉起容器。若无可行节点，Pod 保持 Pending，触发抢占（驱逐低优先级 Pod）或等待重试。

现代调度器基于 **Scheduling Framework** 插件架构，暴露 PreFilter、Filter、PostFilter、Score、Reserve、Permit、Bind 等扩展点，可用 `schedulerName` 指定自定义调度器。注意调度只做"一次性决策"，运行中资源变化不会自动重调度。
